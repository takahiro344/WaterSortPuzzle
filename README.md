# Water Sort Puzzle Solver（不明色1個まで推測対応）

[baclips.com の Water Sort Puzzle 解答アプリ](https://baclips.com/solve-water-sort-puzzle/) の
UI・操作フローをベースに、TypeScript + React で再実装した非公式版です。

オリジナル版は「すべての色が判別できる画像」であることが前提でしたが、本アプリでは
**グリッド上の1マスだけ「不明」に指定しても解ける**よう拡張しています。
（色数と各色の本数（通常は1色あたり4段）が既知であれば、他の色の出現数から
消去法で不明な1マスの色を一意に確定できる、という考え方に基づいています。）

## 使い方

1. **(1/3) 画像選択**: Water Sort Puzzle を1手も動かす前のスクリーンショット（または
   その写真）を選択します。
2. **(2/3) グリッド調整**: 四隅のハンドルをドラッグし、各試験管の色の中心にグリッドの
   交点が来るように調整します。1枚の画像に収まらない場合は `g+` でグリッドを追加し、
   複数グリッドに分けて全ての試験管を読み取ることもできます。
   - `c-` / `c+`: 選択中グリッドの試験管の本数（列）を増減
   - `g-` / `g+`: グリッド自体を1つずつ増減
   - 四隅のハンドル（グリッドの角）はドラッグでグリッドの位置・大きさを調整できます。
   - 4隅を含む交点をクリックすると、画像から検出済みの候補色が一覧表示されます。
     自動判定だけでは色を判別しづらい交点では、候補色を**複数チェックして**
     「色を反映」を押すと、その交点を「候補のどれか」という曖昧な状態として
     登録できます。曖昧な交点が複数あっても、[解く] を押すとすべての組み合わせを
     解けるパターンが見つかるまで自動で順に試すため、手動で1パターンずつ
     試行錯誤する必要がありません（組み合わせ数が多すぎる場合はエラーを
     表示します）。「自動判定に戻す」で画像からの自動判定に戻せます
   - 画像に写っていない空の試験管がある場合は「空の試験管の数」に入力
3. **[解く]** を押すと、色を自動クラスタリング（かつ不明マスがあれば推測）した上で
   最短手順を探索します。
4. **(3/3) 解答**: `+` / `-` ボタンで手順を1手ずつ確認できます。

画像処理・パズルの求解はすべてブラウザ内（クライアントサイド）で行われ、
画像やパズルの内容がサーバーに送信されることはありません。

## 技術構成

- TypeScript + React（Vite）
- グリッド編集 UI は2階層構成
  - `src/components/GridEditorBase.tsx`: グリッド（複数可）の配置・ドラッグ操作、
    列数増減、AUTO/EMPTY/UNKNOWN の状態管理、求解前のセル値確定など本体ロジック
  - `src/components/GridEditor.tsx`: `GridEditorBase` をラップし、通常の交点タップ時に
    候補色選択 UI（色選択ドロップダウン＋「色を反映」「自動判定に戻す」）を表示する
    レイヤーを追加。候補色は複数チェック可能で、手動指定した色（1個以上の配列）は
    `overridesRef` で管理する。求解時に `GridEditorBase` が返す結果へ上書き反映しつつ、
    2個以上の候補が指定された交点は `ambiguousCells`（曖昧セル一覧）として
    `App.tsx` に渡す。すでに単一色へ確定済みのセルが使った色IDは、他の曖昧セルの
    候補から自動的に除外する（チェックの外し忘れによる矛盾した組み合わせを防ぐ）。
    候補色一覧の集計（`collectAvailableColors`）は、自動クラスタリング
    （`colorLogic.clusterColors`）と同じく、グループの代表色をそのグループに
    合流した全ピクセルの平均値（重心）として都度更新する。以前は最初に合流した
    1ピクセルの値に固定していたため、`clusterColors` 側を重心更新に直した際に
    二つの実装の代表色がずれ、候補として選んだ色が求解時に別の色IDへ解決されて
    しまうことがあった。候補色のhexを既存パレットの色IDに対応付ける際
    （`resolveHexToPaletteIndex`）は、候補色一覧の集計（`collectAvailableColors`）と
    自動クラスタリング（`colorLogic.clusterColors`）が別々にピクセルをサンプリング
    していることによるわずかな誤差を吸収するため、自動クラスタリングと同じ
    `CLUSTER_THRESHOLD` を使って最も近い色に対応付ける（しきい値が厳しすぎると、
    本来同じ色のはずの交点が孤立した別の色として扱われ、常に解けなくなる）
- 色取得: `<canvas>` 上でグリッド交点付近のピクセルを平均し、色距離でクラスタリング
  - 候補色一覧は、画像から自動判定した色と手動指定した色をあわせて集計したもの。
    すでに4個検出済みの色であっても、別の交点の誤判定を修正したい場合などのために
    候補から除外せず一覧に表示する
- 不明色推測: `src/colorLogic.ts` の `inferUnknownColor`
  - 各色の出現数をカウントし、「あと1個で規定数（段数）に達する色」が1色だけあれば
    それを不明マスの色として採用
  - 該当する色が無ければ、未検出の新しい色として補完
  - 複数の色が該当する場合は一意に決定できないためエラーを表示
- パズル求解: `src/solver.ts`
  - 状態空間を優先度付きキュー（ベストファースト探索）で探索
  - 「分割注ぎ」は不可（移動元の同色連続分がすべて移動先に収まる場合のみ移動可）という
    オリジナル版と同じルールを採用
- 複数候補セルの自動探索: `src/App.tsx` の `solveWithAmbiguousCells`
  - グリッド調整画面で1つの交点に複数の候補色をチェックすると、その交点は
    `ambiguousCells`（曖昧セル）として扱われる
  - [解く] を押すと、曖昧セルの候補色の組み合わせを1つずつ盤面に反映して
    `solve()` を呼び出し、最初に解けた組み合わせを解答として採用する。
    同じ色が複数の曖昧セルに重複して割り当てられる組み合わせ（実際の盤面では
    起こり得ない）は `cartesianProductWithoutDuplicates` により生成段階で
    除外する。組み合わせ数が上限（既定300通り）を超える場合は自動探索を行わず
    エラーを表示する
  - 各組み合わせは `solve()` を呼ぶ前に `findCapacityMismatch` で色の出現数を
    チェックし、いずれかの色がちょうど capacity 個になっていなければ（＝盤面として
    物理的にあり得なければ）スキップする。全組み合わせがこれに該当した場合は
    「解けるパターンが見つからない」ではなく、どの色の出現数がいくつだったかを
    含む専用のエラーメッセージを表示する
  - 候補の組み合わせを（色の重複しないもの）すべて試しても解けなかった場合だけ、
    次善策として `solver.ts` の `findExposeSequence` を呼び出す。これは
    曖昧セルの位置に「他のどの色とも一致しない仮の色ID」を割り当てた盤面に対して
    BFS 探索を行い、色を決め打ちせずに、いずれか1つの曖昧セルをその試験管の
    一番上まで露出させる最短手順を探す機能。実機でその手順通りに動かせば、
    そのマスの正体が分かり、候補色を絞り込んでから再度解析できる。見つかった
    手順は、通常の解法表示（`SolutionViewer`）と同じステップ再生UIで表示される
    （タイトル・説明文だけ専用のものに差し替え、`unknownCells` でまだ色が
    確定していないマスを破線＋「?」で示す）。盤面全体が解けなかった場合、
    誤解を避けるため盤面プレビューは表示しない

## ローカルでの動作確認

### Docker（推奨）

```bash
docker compose up --build
```

起動後、ブラウザで `http://localhost:8080` を開いてください。

停止するには:

```bash
docker compose down
```

### Docker を使わない場合

```bash
npm install
npm run dev
```

`http://localhost:5173` を開いてください。

## ディレクトリ構成

```
src/
  types.ts           型定義（色ID、EMPTY/UNKNOWN/AUTOなど）
  priorityQueue.ts    探索用の優先度付きキュー
  solver.ts           パズル求解ロジック
  colorLogic.ts        色クラスタリング＆不明色推測ロジック
  paletteDisplay.ts    色ID→表示色の変換
  components/
    ImageUpload.tsx     画像選択（(1/3)）
    GridEditorBase.tsx  グリッド調整・色取得の本体ロジック（(2/3)）
    GridEditor.tsx      GridEditorBaseをラップし、候補色選択UIを追加
    SolutionViewer.tsx  解答ステップ表示（(3/3)）
  App.tsx              画面遷移の管理
  main.tsx             エントリポイント
Dockerfile             マルチステージビルド（Vite build → nginx配信）
docker-compose.yml
nginx.conf
```

## 制限事項

- 移動ルールは「分割注ぎ不可」（オリジナル版 v.2026-04-09 と同様）を前提としています。
- 1色あたりの段数（試験管容量）はグリッドの行数と一致させてください（既定4）。
